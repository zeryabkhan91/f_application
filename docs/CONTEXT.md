## Design interpretations

The blueprint lists a few cached fields alongside instructions to avoid redundant
financial state. Invoice paid/balance amounts and inventory quantity available are
derived through SQL views instead of independently writable columns. NumberSequence
owns prefixes; OrganizationSettings does not duplicate them. Attachments reference
private S3 object metadata instead of persisting expiring/public download URLs.

UnitDefinition holds platform units; Unit holds organization-specific copies and
future custom units. Country and currency codes use platform reference catalogs.
PKR, Pakistan, and Asia/Karachi are configurable organization defaults, not fixed
tenant identifiers. One organization is seeded per demo tenant, while the schema
and tests support multiple organizations and memberships from the beginning.

Tenant IDs, organization IDs, record IDs, and seed role IDs are generated by the
database. No fixed tenant identifiers, cloud credentials, or demo login password
are committed. Demo owners are INVITED until a later authentication flow activates
them. Runtime membership checks deliberately deny invited users access.

## Task #2 — API platform infrastructure (complete)

Shared plumbing for every business module, documented in
[API platform](architecture/api.md). No business endpoints or authentication flows
were added. The existing `GET /api/v1` service-info route moved onto the new helper.

- `organizationRoute`/`publicRoute` declarations register handlers, validate input
  and output, enforce permissions in a `withOrganization` transaction, and generate
  `docs/openapi.json`. Modules live in `apps/api/src/modules/<domain>/`.
- An `Authenticator` seam fills `res.locals.auth` (default: deny all, so organization
  routes answer 401 until Task #3 provides sessions).
- `{ data }` / `{ data, meta }` envelopes and a shared list query: page, pageSize
  (20, max 100), search, per-resource sortBy allow-list, sortOrder, dateFrom, dateTo,
  and resource filters.
- Error envelope gains `fields`. Domain, permission, Prisma, and PostgreSQL errors map
  to stable codes with plain-language messages. Technical detail goes to logs only.
- Exact money library and Decimal/BigInt serializers in `@repo/utils` (decimal.js).
- `recordAudit` with redaction and a new `audit_logs.reason` column.
- Member-private `idempotency_keys` table (RLS) with replay/conflict semantics.
  Lock-order-safe `lockRows`.
- Request logs carry user/tenant/organization IDs, never bodies or credentials.

Decisions: idempotent routes _require_ the header (428 otherwise) rather than treating
it as optional, because double-submitted payments are the risk being prevented.
Failed requests do not store a key, so retries re-execute. Header subtotals are gross
line amounts, with discounts and taxes aggregated, so header CHECKs hold. Validation
error messages now read "Please correct the highlighted fields." (§40).
